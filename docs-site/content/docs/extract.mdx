**本页回答**：结果 zip 怎么变成 outDir 里的文件；zip 里哪些条目会被搬、哪些被拒；产物为什么要么整份出现、要么一个字节不动；
outDir 已有产物时怎么处置；中英文怎么判。它在系统里的位置是[首页](/docs)的接缝 ⑧、⑩、⑪、⑫。

这个模块不知道 zip 从哪来（地址是[云端客户端](/docs/mineru-client)轮询出来的），不知道作业账（它只回一份结果），
也不知道 outDir 之后被谁用、文件该叫什么——出了 outDir 都是调用方的事。它用到的只有 `adm-zip`（构建时由 esbuild
打包进 `dist/`，产物里没有它的包名）、全局 `fetch`、`node:fs`。

## 一条路径，两个入口

下载 zip → 在工作根留一份归档 → 认出 markdown → 围栏检查每一条 entry → 在工作根的 staging 里解完 → 整个改名成 outDir → 判语言。
`downloadExtract(zipUrl, outDir, options)` 从下载开始；`extractArchive(归档, outDir, options)` 从盘上那份归档开始，不碰网络，
`pdf2md.recover` 走的就是它。两条入口共用同一套围栏与同一个提交点。

{/* ref file="../plugins/mineru/src/core/extract.ts" lines="117-151" hash="567760f050ad" blob="1ec2fd1acdda" */}

回给调用方的结果：`markdown` 是 outDir 里那份完整 markdown 的文件名（如 `full.md`）；`files` 是相对 outDir 的 POSIX 路径清单；
`skipped` 是没搬的条目（zip 根上的 `layout.json` 之类，列出来，不悄悄丢掉）；`archive` 是归档路径；`commit` 说这次是新建（`created`）
还是覆盖（`replaced`，旧产物在 `backup`）。

{/* ref file="../plugins/mineru/src/core/extract.ts" lines="71-93" hash="314fb2467416" blob="1ec2fd1acdda" */}

失败时抛三种错误：`ArchiveError`（zip 结构不对：找不到 markdown、候选不唯一、markdown 不在根下）、`EntryRejectedError`
（某条 entry 过不了围栏，带 `entry` 与 `reason`）、`CommitRejectedError`（提交点拒绝，带 `outDir`，outDir 一个字节没动）。
归档已经写到磁盘时三种都带 `archive`，调用方凭它重新解包，不必再问云端要。

## 围栏：全部检查完才写

每条 entry 的名字要过六关：空名、控制字符、反斜杠（Windows 上它也是路径分隔符，落点说不清）、冒号（盘符或 NTFS 备用数据流）、
绝对路径、`..` 段。两条 entry 归一后落到同一处，或者一条既是文件又是另一条的父目录，同样拒。**有一条不合格，整个 zip 一个文件都不写**，

## 提交点：整个改名

解包全在工作根的 `staged-<作业号>/` 里做完，提交时把它整个改名成 outDir。所以 outDir 要么还是上一版（或不存在），要么是完整的新版。
提交点也是处理并发的地方：outDir 在检查之后、改名之前被别人占了，Windows 回 EPERM / EEXIST，这里翻成 `CommitRejectedError`，说明 outDir 没动。

{/* ref file="../plugins/mineru/src/core/extract.ts" lines="285-344" hash="c8ac7bdf8510" blob="1ec2fd1acdda" */}

outDir 不存在或是空目录，直接提交；里面有东西而这次没带 `overwrite`，拒绝，一个字节不动；带了 `overwrite`，旧产物先整个改名进工作根的
`backup-<时间>/`，再放新的。备份不自动清，那是调用方的东西。

覆盖要改名两次（旧的进备份、新的进来），中间断电会留下「outDir 不在、旧产物在备份里」。所以覆盖前先写一份 `commit-journal.json`；
下次对同一个 outDir 解包时，发现 journal 而 outDir 不在，就把旧产物搬回去——宁可退回上一版，也不给调用方一个产物不见了的目录：

## 判中英文

中文字符数 × 3 ≥ ASCII 字母数就判 `zh`，否则判 `en`。这是通用的文本判断，跟论文库无关；调用方拿 `lang` 去定自己的文件名。

## 怎么测

仓根 `pnpm check` 会跑 `tests/extract.test.mjs`：围栏的七种违规各一条（`..` 段、反斜杠、盘符、绝对路径、备用数据流、控制字符、
归一后一段都不剩），坏条目混在好条目里时整个 zip 一个文件都不写，提交点的默认拒绝与显式覆盖，outDir 是文件，两条解包同时抢一个 outDir，
以及归档写好后不联网再解一遍。云端与真 PDF 都不出现：`fetch` 是替身，zip 是测试里用 adm-zip 现场生成的（`tests/helpers.mjs`）——
`addFile` 会把 `..` 归一掉，所以先用占位名加进去、再把 `entryName` 改回原样。`commit-journal.json` 的回滚没有测试。
