# 云端客户端：MinerU v4 三动作

**本页回答**：MinerU 云端那三次握手各自怎么走；什么算终态、什么算停滞；超时为什么是「结算为
failed」而不是抛错；回包里的错误怎么认。

## 管什么

三个动作：`requestUpload`（申请上传位，回 `[batch_id, upload_url]`）、`upload`（PDF 二进制
PUT 到预签名 URL）、`poll`（轮询到终态，沿途把非终态回包交给回调）。外加 `isDone` 判定、
`MineruError` 业务错、`MAX_FILE_BYTES` 云端单文件上限。

## 不知道什么

- 不知道作业、账、作业号——那是[作业机](/docs/job-runner)的事，这里只认调用方递进来的
  token 与 batchId；进度交给 `onProgress` 回调之后记不记、怎么记也是作业机的事
- 不知道 token 从哪来——settings 那层的事
- 不知道结果怎么落盘——拿到 `full_zip_url` 后的事在[解包与语言](/docs/extract)

## 提供的接口

| 名字 | 是什么 |
| --- | --- |
| `requestUpload(token, name)` | 申请上传位，回 `[batchId, uploadUrl]` |
| `upload(uploadUrl, pdfPath)` | PUT 二进制，不带 Content-Type（接口规格如此） |
| `poll(token, batchId, options)` | 轮询到终态；被打断抛 AbortError，停滞或超总上限**结算为 failed** |
| `isDone(result)` | `state === 'done'` |
| `MineruError` | 回包带业务错误码（`code` / `msgCode` 非 0）或形状不对时抛 |
| `MAX_FILE_BYTES` | 云端单文件上限 200MB，作业机在 submit 时本地先挡 |

轮询的旋钮全在调用方手里——节奏、停滞上限、总上限、进度回调、打断信号：

## 依赖的接口

只有全局 `fetch` 与 `AbortSignal`，外加 `node:fs` 读文件。零 gwb 依赖、零 cordis 依赖——
这是个纯 node 模块，拿起就走。

## 怎么单独测

纯函数模块，喂假 `fetch` 就能直测：排队不判停滞、解析中页数不动判停滞、总上限、几种错误回包
的翻译。仓里没有单测设施，这组验证落在 `probes/2609172224_poll-and-live-run/`（冻结产物 +
零依赖脚本）；真链路要真 token、真云端，见[作业机](/docs/job-runner)怎么单独测。

## 代码地图

- **在哪**：`src/core/mineru.ts`，一个文件
- **先读**：`poll`
- **读序**：`requestUpload` → `upload` → `poll`（循环体：`readResponseData` 取回包 → `toFileResult` →
  终态判断 → 交 `onProgress` → 停滞与总上限判断 → `sleepUnlessAborted` 等下一轮）
- **可跳过**：`sleepUnlessAborted` / `parseJsonRecord` / `asRecord` 这类几行的小函数

## 设计点（错了难改的那几条）

**超时不抛，结算为 failed，而且分两道**：云端在干活（`running` / `converting`）时，状态与
已解析页数一段时间都不动才算**停滞**；排队（`waiting-file` / `pending`）不判停滞——排多久是
云端配额与优先级的事，只受连排队在内的**总上限**管。两种都不是异常，是这条解析链的一种终局，
err_msg 写明是哪一种、并提醒云端可能还在跑：

{/* ref file="../plugins/mineru/src/core/mineru.ts" lines="104-123" hash="7159ac02373f" blob="8aab970ebcb2" */}

**先认回包，再认状态码**：token 错走的是 HTTP 401、错误码的键叫 `msgCode`；任务不存在之类
走 HTTP 200、键叫 `code`。只看状态码就会把 token 错吞成一句「HTTP 401」（形状实测见
`probes/2609172223_api-error-shapes/`）。认得出的错误码附一句调用方照着就能做的话，认不出
回包的非 2xx 才报 HTTP 错：

不等满一轮间隔：

**接口那组是一批多文件，这个件一作业一文件**：申请上传位的 `files` 数组长度恒为 1，语义不变——
聚合进一个 batch_id 曾被实测否决（同样文件聚合 3/3 解析失败、拆开 2/2 过，见
[那张卡](/trajectory/2026-09-18-parallel-and-serial-overturned)），并行靠 N 个独立任务实现，
不靠批聚合。申请时钉死 vlm 模型、公式表格都开、语言 `ch`（云端缺省，中英混合）：
