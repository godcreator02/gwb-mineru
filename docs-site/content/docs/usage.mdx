## submit 收一个数组，立即返回

```json
{ "files": [{ "input": "D:/papers/a.pdf", "outDir": "D:/papers/a" }, { "input": "D:/papers/b.pdf", "outDir": "D:/papers/b" }] }
```

回的是作业数组，每条 `state: "queued"`——**返回不是完成**。两篇在后台同时跑，`pdf2md.jobs` 里看到几条 `running` 是正常的；
终态查 `pdf2md.status`，或等 `job-settled` 事件。问的间隔 5 到 10 秒就够，到了终态别再问。

`submit` 检查整批：`input` 与 `outDir` 都要是绝对路径，`input` 是存在的文件且不超过 200MB，token 已配置，outDir 收得下这条作业
（见下一节）。有一条不合格整批拒，一条账都不写、云端一次都不问。作业账写不进磁盘（数据盘满之类）同样整批拒：
回了作业号，就要保证宿主重启后还查得到它。

轮询 5 秒一次。云端在解析时，状态与已解析页数 10 分钟没动判停滞；连云端排队在内 1 小时没完判超时；两种都记成 `failed`，
`error` 里写是哪一种。解析中的作业带 `progress: { extractedPages, totalPages }`，云端排队时没有它。

`done` 的作业带三样产物：`markdown`（outDir 里那份完整 markdown 的文件名，通常是 `full.md`）、`lang`（`zh` 或 `en`，按中文字符占比判）、
`files`（写进 outDir 的文件清单）。正文里的图是 `images/xxx` 相对链接，跟 markdown 同层，不用改。另有三个字段说明产物怎么进的 outDir：
`commit`（`created` 新建、`replaced` 覆盖）、`backup`（覆盖时旧产物挪去的备份目录）、`skipped`（zip 里没搬的杂项，如 `layout.json`）。

## outDir 的两条规矩

**一个 outDir 同一时间只归一条作业。** 同一批里两条指向同一个 outDir，或者 outDir 正被一条还在跑的作业占着，整批当场拒，
报错里写出占着它的作业号。两条作业往同一个目录里解，先完成的那条记下的文件清单马上就不准了。

**outDir 里已经有东西时默认拒。** 提交时就拒，不排一条到最后注定失败的作业。要覆盖，在那一项上写 `"overwrite": true`：
旧产物先整个挪进 outDir 旁边工作根里的 `backup-<时间>/`，再放新的；备份不会自动清。outDir 不用预先建，
产物是在工作根里解完、最后一步整个改名成 outDir 的，所以中途失败时 outDir 还是上一版（或还不存在），不会新旧混在一起。

## 解包失败时用 recover，不必再花一次额度

结果 zip 下载下来先在工作根留一份：`D:/papers/a` 的归档是 `D:/papers/.a.pdf2md/archive-<作业号>.zip`。解包那一步失败时
（围栏拒了某条 entry、提交时 outDir 被别人占了、磁盘读写出错），作业记成 `failed`，账上带着 `archive`。这时调
`pdf2md.recover { "id": "<作业号>" }`，插件用这份归档把解包重做一遍：不申请上传位、不上传、不轮询，不花云端额度。

`recover` 只收 `failed` 与 `interrupted` 的作业：`done` 的产物已经在 outDir 里，还在跑的不能插手。账上没有 `archive` 的
（上传或轮询阶段就失败了）会直接告诉你没有归档，要结果只能重新 `submit`，会再花一次额度。

没配时 `submit` 报「MinerU token 没配」：

配置命令是 `settings.set { "section": "mineru", "key": "token", "value": "…" }`。状态回执与日志里永远看不到它的值。
`submit` 每次调用时读一次 token，改了值不用重新加载插件。

token 配了但无效或过期，`submit` 拦不住（要问云端才知道），作业几秒内 `failed`，`error` 里带 `code=A0211` 与换 token 的那句话；
换完重新提交即可。

## 事件

作业到 `done` 或 `failed` 时，插件经内核推一条事件：`{ source: "gwb-mineru", type: "job-settled", jobId, ok, outDir, error? }`，
在作业账写进磁盘之后才发。事件给看着界面的人用；agent 照样查 `pdf2md.status`。

## 出了问题怎么看

- **`interrupted`**：宿主重启或插件卸载打断了作业，账上如实标着。账上有 `archive` 的用 `recover`；没有的重新提交同一个 PDF。插件不会自己接着跑
- **失败原因看 `error`**：上传失败、解析失败、停滞或超时、zip 结构不对、云端业务错误都写在这里，日志里是同一句。认得出的云端错误码
  （token 失效、超 200MB、超 200 页、当天任务数到上限）后面附一句照着就能做的话；网络层失败 `fetch failed` 的括号里是真正的原因
  （`ECONNRESET` 之类）。mineru.net 的连接偶尔会断，与并发无关（只交一篇也会遇到，重试就过），看到它重新提交就好
- **「outDir 里已经有 N 项东西」**：这一项没带 `overwrite`；**「outDir 正被作业 X 占着」**：那条还在跑，等它结束或换个目录。
  两种拒绝都不动磁盘上的东西

给 agent 的说明书在包里的 `skills/pdf2md/SKILL.md`，经说明书插件登记；没装说明书插件的 home 里插件照常加载。
