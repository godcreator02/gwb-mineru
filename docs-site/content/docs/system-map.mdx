# 系统地图

**本页回答**：一句 `pdf2md.submit` 之后发生了什么；这个插件分几块代码、各自管什么；产出落在盘上哪里。

## 三块代码

{/* tree dir="../plugins/mineru/src" depth="2" */}

| 模块 | 是什么 | 详见 |
| --- | --- | --- |
| **作业机**（`src/index.ts`） | cordis 服务 `gwbPdf2md`：收一批作业（数组）、秒回、各跑各的全链、状态推进落账、重启对账、卸载打断。命令 `pdf2md.*` 也在这层登记 | [作业机](/docs/job-runner) |
| **云端客户端**（`src/core/mineru.ts`） | MinerU v4 API 的三个动作：申请上传位、PUT 上传、轮询到终态（停滞与总上限判定、回包错误翻译也在这）。纯函数模块，不认识作业 | [云端客户端](/docs/mineru-client) |
| **解包与语言**（`src/core/extract.ts`） | 下载结果 zip、原样解进 outDir、认出 markdown、判 zh/en。纯函数模块，不认识云端 | [解包与语言](/docs/extract) |

依赖方向单向：作业机 → 云端客户端 → （网络）；作业机 → 解包。后两块互相不认识，都是作业机手里的工具。
`src/vocab.ts` 只有 `isRecord` 与 `requireKernel` 两个无状态小函数：词汇表包 `@godcreator/gwb-plugin-api` 只有类型，这两个函数由插件自带一份。

## 一条作业从提交到终态

状态机六态，`done` / `failed` / `interrupted` 是终态：

```
queued → uploading → running → done | failed
   \──────── 重启或插件卸载 ────────→ interrupted
```

1. `pdf2md.submit`（或消费方调 `gwbPdf2md.submit`）收**数组**：整批验绝对路径、验文件在且不超
   200MB、验 token 配了、验每个 outDir 收不收这条作业（里面有东西而没带 `overwrite` 就拒）、
   **同步占住每个 outDir**、落完账，**秒回作业号数组**——返回不是完成；有一条坏形状整批当场拒，
   不落半批账，两条作业瞄同一个 outDir 同样当场拒
2. 各自开跑、互不排队：每条作业独立走全链（报名 → PUT 上传 → 轮询（5 秒一问；解析中页数
   10 分钟不动判停滞，连云端排队总上限 1 小时）→ 下载 zip 到工作根留一份归档 → 围栏校验全部
   entry → 解进 staging → 原子提交进自己的 outDir）——一次交 N 篇，`pdf2md.jobs` 里 N 条同时
   `running` 是常态
3. 每步推进都落账（gwbData，`jobs` 文档，写盘排队），云端报的进度变了也落账；到达终态经内核
   emit 通道推一条 `job-settled` 事件
4. 宿主重启：上次留下的非终态作业标 `interrupted`——不丢账、不假装还在跑，也不自动重跑
5. 解包那一段失败时账上记着归档路径，`pdf2md.recover` 凭它零云端重解一遍

## 盘上有什么

| 位置 | 是什么 |
| --- | --- |
| `<outDir>/full.md` | 完整 markdown（名字以作业 `markdown` 字段为准，通常是 full.md） |
| `<outDir>/images/…` | 正文引用的图，跟 md 同层的相对链接，不用改 |
| `<outDir>` 同级的 `.<outDir 名>.pdf2md/` | **工作根**：`archive-<作业号>.zip`（原始 zip 的落盘副本，recover 凭它）、`backup-<时间戳>/`（覆盖时挪出来的上一版）、staging 与提交 journal（都是过路的）。调用方随时可以整个删掉——正在跑的那条作业除外 |
| `<home>/node_modules/@godcreator/gwb-mineru` | 插件本体；进 home 走 `plugin-manager.install {"pkg":"@godcreator/gwb-mineru"}`（条目 id `mineru`，设置节随它） |

作业账经 gwbData 存在 home 的数据区（文档名 `jobs`），不在上面这些目录里。

## 速查

| 什么 | 值 |
| --- | --- |
| 检查 | 仓根 `pnpm check`：对 `plugins/*` 逐个 typecheck，再构建并跑单测 |
| 构建 | 仓根 `pnpm build`：插件包里 `build.ts` 用 esbuild 输出 js，把 adm-zip 打包进产物（产物里的包名 import 只剩 node 内置模块与 `cordis`），再由 tsc 按 `tsconfig.build.json` 只输出类型声明 |
| 依赖 | peer 是 `cordis`（服务类按值继承它的 `Service`）、内核包与用到的四个插件（commands、data、settings，说明书插件 skills 标 optional）；adm-zip 在 dev，打包进产物 |
| 文档站 dev | `pnpm dev`（docs-site 下），端口 4317 |
| 凭据 | settings 节 `mineru`，键 `token`（secret），mineru.net 的 API 管理页创建 |
| 实验材料 | 仓根 `probes/<时间戳>_<目的>/`，一次实验一个目录 |
| 事件 | `source: "gwb-mineru"`、`type: "job-settled"`，载荷带 jobId / ok / outDir / error |
