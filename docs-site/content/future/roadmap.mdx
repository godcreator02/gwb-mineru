## 在等前提

| 东西 | 在等什么 |
| --- | --- |
| 一批多文件 | 形状已探明（`probes/2609181225_batch-shape`）：一个 batchId 每文件独立终态、坏文件不连坐——批量可以只做传输层，账不必跟着变。等第二个真实消费方带着「一批」的形状来，再议 API 面怎么开；现在的恒为 1 数组就是为此留的缝 |
| 暴露转换参数 | `ocr` / `pageRanges` / `language` / `model` 现在钉死在客户端里（vlm、不开 OCR、ch）。等调用方带着真需求来——扫描版老论文要 OCR、只转某几页——再给 submit 加可选参数 |
| 重试策略 | 续取落地后，「超时/打断后重提重复扣额度」的疼已被挪走大半；剩下的是云端真失败后的重提。等某个调用方真在现场撞出「重提都很疼」的局面——到时候策略归那个调用方，件只考虑要不要留钩子 |
| 单测设施 | 第一个纯函数模块真出过回归的那天。现在 typecheck 加真链路实跑够用，不为「将来可能要」先搭 |
