docfirst 按接缝拆了包，要发一组破坏性版本。本站的 `devDependencies` 里现在是 `@godcreator/docfirst-workflow` 0.3.1
与 `@godcreator/docfirst-trajectory` 0.1.1，照旧能用；要用新版时照下面改，不急。

**包怎么装**：站的 `devDependencies` 只写 `@godcreator/docfirst-workflow` 0.4.1，删掉 `@godcreator/docfirst-trajectory`。
它停在 0.1.1、不再更新；星轨盘改名 `@godcreator/trajectory-disk`，由 `docfirst-workflow` 带上，站不直接依赖它。
站里接 fumadocs 的部分（集合选项、组件名册、状态点与术语组件、星轨盘组件 `StarDisk` 与样式）都从 `@godcreator/docfirst-workflow`
的 `./fumadocs`、`./fumadocs/roster`、`./fumadocs/pre`、`./fumadocs/term`、`./fumadocs/trajectory` 与 `./fumadocs/*.css` 取，
`@godcreator/docfirst-trajectory/server` 没有了。不要装 `@godcreator/docfirst-fumadocs`：它只发过一个 0.1.0，已经并进 `docfirst-workflow`。
接线照新站模板改：docfirst 仓 `plugins/docfirst/template/`，也就是 `docfirst.create` 建站时写的那几份文件。

**记录与记号**：
- 不再认 `.ledger.json` 记录簿，没有迁移命令：还用记录簿的站先用 0.3.x 的 `docfirst migrate-ledger` 把记录写进记号，再升
- 不再认草稿记号 `@@docfirst … @@`：改写成不带记录的正式记号，`check` 会逐行指出来
- `has` 记号直接报错，报错里给出改成行段的写法；`exists` / `absent` 也没有了。换成行段后第一次 `confirm` 会多出一批黄灯，逐条复核再 `--accept`

**分区**：`content/` 下只有 `trajectory/` 与 `future/` 两个名字固定，其余目录都是现状区。旧的 spec / feedback / outputs 三个区挪进
`future/`（在途方案 `future/spec/`、别的仓投来的反馈 `future/inbox/` 一条一个文件）与现状区（生成正本放现状区，比如
`docs/outputs/`），改配置与路由；配置里的 `formats` 那一行删掉。站的 `src/components/` 下的代码文件从此进 `check`，只有写了记号的才报状态。

**轨迹卡的写法变严**，不合格的卡照样画上星轨盘，但每条问题都算红：
- 一个卡目录只有一张根卡，其余卡的 `parent` 只写根卡的身份，而且写成列表：`parent: [根卡身份]`
- 卡与卡之间的关系写在正文的关系行里，只认标准 md 链接：`pivots-from:: [标题](卡身份.mdx)`、`supersedes:: [标题](卡身份.mdx)`；
  wikilink、目标包在 `<>` 里的都算格式不对；关系不能指向根卡，也不能指向盘上没有的卡
- 同一身份 `.md` 与 `.mdx` 两个文件都在报一条，只认 `.mdx`；根卡 `## 里程碑` 里以 `- ` 开头却写坏的行报一条
- `docfirst trajectory --json` 的输出改成 `{ center, cards, sick, trees }`

升级后先在站目录跑一次 `pnpm doc`（`docfirst check`），按它逐条报出来的改；写法的正本是说明书 `docfirst-docs` 与 `trajectory`
（工作台插件 `@godcreator/gwb-docfirst-workflow` 带的，`run skill.read`），以及 docfirst 仓的文档站。
